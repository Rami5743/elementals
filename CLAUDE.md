@AGENTS.md

## This repository

Thirty finished levels of our own live in `levels/`, published to `index.html` and GitHub Pages.
Work on `main`.

- **Before designing anything, read `catalog/BRIEF-<n>p.md`** for the player count you are
  building for: the novelty bar for that count, the next free `order`, which ideas are used there
  and which are untouched. `catalog/LEVELS.md` has every level of every count in full, and
  `catalog/MAPS.md` the maps of this repo's levels; all are generated by `node tools/catalog.mjs`.
- **`catalog/PHYSICS.md`** is the measured table — jumps, gaps, fans, rolling boulders, pulleys. Read it
  rather than writing a probe: those numbers are constants, measured once.
- **Invent a new idea for each level.** Failing that, use an idea no level of the same player count
  has used; and only failing that, a new combination of old ideas. Levels for different player
  counts may share freely, and repeating ingredients (ice, flames, turbines, cracked floors) is
  never a problem. The vocabulary is `tools/ideas.mjs`, `node tools/novelty.mjs <id>` checks a level
  and says which of the three it managed, and `node tools/roll-features.mjs <n>` is the fallback
  when nothing is invented.
- The **`new-level` skill** (`.claude/skills/new-level/`) is the full procedure, including the
  measured behaviour of the simulation in `references/engine-facts.md` — read that before writing
  tiles or a solution script; most of it is not guessable.
- The page's dodecahedron icon is `icon.svg`, generated by `node tools/make-icon.mjs`; the
  `<head>` and header that use it live in `tools/build.mjs`, not in `index.html`.
- After `kit.mjs check` passes, run `node tools/build.mjs` **and** `node tools/catalog.mjs`, or the
  level is invisible to the page and to the next novelty check.
- The page dates every level (**Added** / **updated**) from the git history of its `level.json`,
  `solution.mjs`, `meta.json` and `NOTES.md`, and runs oldest first within each player count, so run
  `tools/build.mjs` in the same commit as a level change, not one commit later, and never hand-edit
  `index.html`. `order` in `meta.json` orders the catalogue, and only breaks a tie on the page
  between levels that arrived in the same commit.
- After any kit update, run `node tools/physics.mjs` and commit the result: `catalog/PHYSICS.md`
  is measured from the simulation, so a kit change can silently invalidate it.
  `node tools/physics.mjs --check` fails when it no longer matches.
- When the published game gains levels, refresh the campaign half of the catalogue with
  `tools/extract-campaign.py` (its docstring has the two curl lines and the follow-up steps). The
  author ships levels from this repo, so that script also marks which campaign levels are ours.
